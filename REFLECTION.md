1. It takes two different delete calls because there's two different things that are saved that need to be cleared to properly delete the front element in the linked list. There is the node itself which is created in the addFront() method. And also the int which contains the data value that the node points to. Which you can see in main when addFront is called and the value parameter is set to a "new int." Both of these need to be cleared out.
2. Like it was mentioned in the previous answer, adding a *  before T makes it so that the array works by pointing to the data rather than storing it within itself. So a destructor is needed for the same reason as the previous answer, it needs to delete the object that was created with new that is otherwise safe to rot away uselessly because it is not contained within the array. If you forgot to add a destructor it would not cause a compiler error, C++ doesn't see that as an issue that requires the program to be stopped. Instead it would cause a buildup of objects that do nothing and are never cleared out. So basically, a memory leak.
3. addFront() takes a lot more control than search() does. It creates a new node to store the pointer within which can be referenced later by deleteFront() to be able to destroy everything. Search never creates anything that stores the value, it's simply a bool method that searches through the linked list and sees if anything matches the value its parameter is provided. Then returns true or false.
4. The two mechanisms that make this possible are polymorphism and factory pattern. The polymorphism comes from the way that the class List is used as an abstract class, because of this LinkedList or ArrayList are never referenced inside main itself. The factory pattern is seen inside of List where it defines all the methods that both LinkedList and ArrayList use but then inside of the makeList() function it can be defined which one will be inserting its functionality.
